# 🚢 线上部署指南（云服务器）

> 目标：把后端部署到自有云服务器（腾讯云 / 阿里云 / 百度云 ECS），
> 并让 **B 站解析、AI 总结、视频下载** 三个核心功能在线上真正可用。

---

## 一、线上与本地最大的区别

| 能力 | 本地开发 | 线上服务器 | 说明 |
|------|----------|------------|------|
| 浏览器导出 Cookie | ✅ `export_cookies.py` | ❌ **无浏览器** | 必须改用环境变量注入 |
| ffmpeg | 可选（static-ffmpeg 自动下载） | ✅ 系统安装 | 高清下载必需 |
| TLS 指纹伪装 | ✅ curl_cffi | ✅ curl_cffi | 需 `yt-dlp[default,curl-cffi]` |
| 磁盘写入 | 本地目录 | 需持久化卷 | 否则容器重建丢文件 |

**最关键的一条**：服务器上没有 Chrome，`export_cookies.py` / `export_cookies_direct.py`
**在线上用不了**。B 站登录态只能通过 **环境变量 `BILI_COOKIE`** 注入。

---

## 二、准备 Cookie（在本地做，不是服务器）

1. 在本地浏览器登录 B 站
2. 用扩展「Get cookies.txt LOCALLY」导出，或跑 `python export_cookies_direct.py`
3. 打开生成的 `cookies.txt`，把**整个文件内容**复制出来
4. 粘到服务器的 `.env.deploy`：

```bash
# 方式 A：整份 Netscape 文件内容（推荐，最完整）
BILI_COOKIE="# Netscape HTTP Cookie File
.bilibili.com	TRUE	/	TRUE	0	SESSDATA	xxxxxx
.bilibili.com	TRUE	/	TRUE	0	bili_jct	yyyyyy
.bilibili.com	TRUE	/	TRUE	0	DedeUserID	12345"

# 方式 B：只填关键三字段（程序自动转 Netscape 格式）
BILI_COOKIE="SESSDATA=xxxxxx; bili_jct=yyyyyy; DedeUserID=12345"
```

> ⚠️ **Cookie 会过期**。`SESSDATA` 通常 30 天失效。失效后 B 站解析会再次报
> `No video formats found`，此时重新导出并更新 `BILI_COOKIE`，然后
> `sudo systemctl restart saveany-backend`。

## 三、方式 A：Docker 部署（推荐）

### 3.1 安装 Docker

```bash
curl -fsSL https://get.docker.com | sh
sudo systemctl enable --now docker
```

### 3.2 拉代码并配置

```bash
git clone <你的仓库地址> /opt/saveany
cd /opt/saveany
cp deploy/.env.deploy.example .env.deploy
vim .env.deploy        # 填 JWT_SECRET / DEEPSEEK_API_KEY / BILI_COOKIE
```

### 3.3 启动

```bash
docker compose up -d --build
docker compose logs -f          # 看启动日志
curl http://127.0.0.1:8000/api/health
```

### 3.4 常用命令

```bash
docker compose restart          # 重启
docker compose down             # 停止
docker compose up -d --build    # 改代码后重新构建
```

> 数据持久化：`backend/downloads`（视频）、`backend/data`（SQLite）已挂载到宿主机。

## 四、方式 B：裸机部署（systemd）

### 4.1 一键脚本

```bash
git clone <你的仓库地址> /opt/saveany
cd /opt/saveany
cp deploy/.env.deploy.example .env.deploy
vim .env.deploy                 # 填真实值
sudo bash deploy/deploy.sh
```

脚本会自动：装依赖（python3/ffmpeg）→ 建虚拟环境 → 注册 systemd → 自检。

### 4.2 手动安装（若脚本不适用）

```bash
sudo apt update && sudo apt install -y python3 python3-venv ffmpeg
cd /opt/saveany
python3 -m venv venv
venv/bin/pip install -r backend/requirements.txt

sudo cp deploy/saveany-backend.service /etc/systemd/system/
sudo systemctl daemon-reload
sudo systemctl enable --now saveany-backend
sudo journalctl -u saveany-backend -f
```

## 五、配置 Nginx 反向代理

### 5.1 安装并配置

```bash
sudo apt install -y nginx
sudo cp deploy/nginx-saveany.conf /etc/nginx/sites-available/saveany
sudo ln -sf /etc/nginx/sites-available/saveany /etc/nginx/sites-enabled/
sudo nginx -t && sudo systemctl reload nginx
```

**必须改** `deploy/nginx-saveany.conf` 里的 `server_name api.your-domain.com`。

### 5.2 HTTPS（强烈建议）

```bash
sudo apt install -y certbot python3-certbot-nginx
sudo certbot --nginx -d api.your-domain.com
```

### 5.3 ⚠️ SSE 流式输出的关键配置

AI 总结走 **Server-Sent Events**，Nginx 默认会**缓冲响应**导致前端收不到流。
配置里已包含，务必确认存在：

```nginx
proxy_buffering off;
proxy_cache off;
proxy_set_header Connection '';
proxy_read_timeout 600s;
```

## 六、上线前检查清单

| 检查项 | 命令 / 说明 |
|--------|-------------|
| 服务在跑 | `systemctl status saveany-backend` 或 `docker compose ps` |
| 健康检查 | `curl http://127.0.0.1:8000/api/health` |
| 端口监听 | `ss -lntp \| grep 8000` |
| 日志无报错 | `journalctl -u saveany-backend -n 50` |
| JWT_SECRET 已改 | 不能用 `CHANGE_ME...` |
| DeepSeek Key 有效 | 余额需 > 0，否则 AI 总结报 402 |
| **BILI_COOKIE 已注入** | `grep BILI_COOKIE .env.deploy` |
| ffmpeg 可用 | `ffmpeg -version` |
| CORS 已配置 | `.env.deploy` 的 `CORS_ORIGINS` 填前端域名 |
| 防火墙开放 | 80/443 对外，8000 **不要**直接对公网暴露 |

## 七、线上功能自检脚本

部署完成后，在服务器上跑一遍：

```bash
# 1) 健康检查
curl -s http://127.0.0.1:8000/api/health

# 2) 解析 B 站（验证 Cookie 是否生效）
curl -s -X POST http://127.0.0.1:8000/api/parse \
  -H "Content-Type: application/json" \
  -d '{"url":"https://www.bilibili.com/video/BV1mAAmzqEfP"}'

# 3) AI 总结（验证 DeepSeek 与 SSE）
curl -N -X POST http://127.0.0.1:8000/api/summarize \
  -H "Content-Type: application/json" \
  -d '{"url":"https://www.bilibili.com/video/BV1mAAmzqEfP"}'
```

**预期**：① 返回 `{"status":"ok"...}`；② 返回视频标题与格式列表；
③ 逐条推送 `subtitle` / `summary` / `mindmap` / `done` 事件。

## 八、常见线上问题

### Q1：Cloudflare / 反代后拿到的是内网 IP
确保 Nginx 传了 `X-Real-IP` / `X-Forwarded-For`（配置里已含）。

### Q2：B 站解析报 `No video formats found`
1. `BILI_COOKIE` 没配 → 补上
2. Cookie 过期 → 重新导出
3. 服务器 IP 被 B 站限流（机房 IP 常见）→ 换 IP 或加代理

### Q3：AI 总结报 `402 Insufficient Balance`
DeepSeek 余额不足，去 https://platform.deepseek.com/top_up 充值。

### Q4：前端请求被 CORS 拦
`.env.deploy` 的 `CORS_ORIGINS` 必须填**前端真实域名**（含 https://），
多个用英文逗号分隔，然后重启服务。

### Q5：SSE 没有流式效果，一次性返回
Nginx 的 `proxy_buffering off` 没生效，检查 `location /api/` 块。

### Q6：下载的视频容器重建后丢失
确认 `docker-compose.yml` 的 volumes 挂载生效，或改用裸机部署。
