# 🚀 微信云托管部署指南（前后端分离）

> 目标：把 SaveAny 的 **FastAPI 后端** 和 **Vue3 前端** 都部署到微信云托管，
> 做到免运维、按量计费、自动扩缩容，并保证 **B 站解析 / AI 总结 / 视频下载** 线上可用。

---

## 一、为什么是微信云托管

| 特性 | 说明 |
|------|------|
| 免运维 | 不用买服务器、不用装环境、不用配 Nginx 系统服务 |
| 按量计费 | 无流量时缩容到 0，学生项目成本极低 |
| 自动扩缩容 | 突发流量自动拉起实例 |
| 容器化 | Dockerfile 打包，本地跑通即可上线 |

## 二、架构总览

```
                    用户浏览器
                        │
        ┌───────────────┴───────────────┐
        ▼                               ▼
┌──────────────────────┐      ┌──────────────────────┐
│  前端服务 (Nginx)     │      │   （同源，无需 CORS）  │
│  saveany-frontend    │      │                      │
│  · 托管 Vue dist     │      │                      │
│  · /api/ 反向代理 ───┼─────▶│                      │
└──────────────────────┘      └──────────┬───────────┘
        │                                │
        │ SPA 路由兜底                   ▼
        │                     ┌──────────────────────┐
        │                     │  后端服务 (FastAPI)   │
        │                     │  saveany-backend     │
        │                     │  · /api/*            │
        │                     │  · yt-dlp + ffmpeg   │
        │                     │  · DeepSeek AI 总结   │
        │                     └──────────┬───────────┘
        │                                ▼
        │                     ┌──────────────────────┐
        │                     │  微信云托管内置 MySQL  │
        │                     │  · users / orders    │
        │                     └──────────────────────┘
```

**关键设计**：前端所有请求都走相对路径 `/api`，由 Nginx 反代到后端 →
**同源访问，彻底规避跨域**，前端代码零改动。

## 三、⚠️ 上线前必须理解的 3 个差异

### 1. 数据库必须换成 MySQL（不能用 SQLite）

微信云托管容器**每次重新部署文件系统都会重置**，SQLite 的 `app.db` 会丢。
而且微信云托管**不支持 CFS 文件挂载**（那是腾讯云托管 CloudBase 的能力）。

✅ 正确做法：用微信云托管的**内置 MySQL**。
代码已改造完毕（`backend/database.py`）：

- 检测到 `MYSQL_ADDRESS` 环境变量 → 自动用 MySQL
- 没检测到 → 本地继续用 SQLite（开发不受影响）
- 自动创建数据库、自动建表，SQL 方言自动转换

### 2. Cookie 必须走环境变量

服务器上没有浏览器，`export_cookies.py` 跑不了。
线上统一用环境变量 `BILI_COOKIE` 注入（代码已支持）。

### 3. 前端不能再用 Vite 开发服务器

线上用 Nginx 托管 `dist` 静态产物（Dockerfile 已做多阶段构建）。

## 五、第一步：部署后端服务

### 5.1 创建环境并开通 MySQL

1. 登录 https://cloud.weixin.qq.com → **新建环境**（例如 `prod`）
2. 进入环境 → 左侧 **MySQL 数据库** → **开通**
3. 开通后平台会**自动注入**三个环境变量到容器：
   - `MYSQL_ADDRESS`（内网地址，如 `10.0.x.x:3306`）
   - `MYSQL_USERNAME`
   - `MYSQL_PASSWORD`

> 若未自动注入 `MYSQL_DATABASE`，程序默认使用 `saveany` 并在首次启动时自动创建。

### 5.2 新建后端服务

1. 环境内 → **云托管** → **新建服务**
2. 服务名称：`saveany-backend`
3. 部署方式：**代码仓库**（推荐，可自动流水线）
   - 代码源：GitHub → 授权 → 选择你的仓库
   - 分支：`main`
   - **代码目录**：`backend` ← 关键！这样才会读到 `backend/container.config.json`
4. 端口：`80`（与 `backend/container.config.json` 的 `containerPort` 一致）
5. 确认创建

### 5.3 配置后端环境变量

进入服务 → **服务设置 → 环境变量**，填写：

| 变量名 | 必填 | 说明 |
|--------|:----:|------|
| `JWT_SECRET` | ✅ | 强随机串，生成：`python -c "import secrets;print(secrets.token_urlsafe(48))"` |
| `DEEPSEEK_API_KEY` | ✅ | DeepSeek 密钥，余额需 > 0 |
| `BILI_COOKIE` | ✅ | B 站登录态，格式见下方 |
| `PAYMENT_DISABLED` | 建议 | `true` = 关闭支付，AI 总结免登录免付费 |
| `CORS_ORIGINS` | 建议 | 前端域名，如 `https://你的前端域名` |
| `TZ` | 可选 | `Asia/Shanghai` |

> ⚠️ 敏感变量**只在控制台配置**，绝不要写进 `container.config.json`（那会提交到 git）。

### 5.4 BILI_COOKIE 的正确填法

微信云托管控制台的输入框不适合粘贴多行文本，**请用单行分号格式**：

```
SESSDATA=你的SESSDATA值; bili_jct=你的bili_jct值; DedeUserID=你的UID
```

#### 这三个值从哪里来？

**方法一：浏览器开发者工具（最快，不用跑脚本）**

1. 浏览器打开并登录 https://www.bilibili.com
2. 按 `F12` 打开开发者工具
3. 切到 **Application** 标签（Chrome/Edge 中文版叫「应用程序」）
4. 左侧展开 **Cookies** → 点击 `https://www.bilibili.com`
5. 在右侧列表中找到下面三行，复制各自的 **Value** 列：

| Cookie 名称 | 说明 |
|-------------|------|
| `SESSDATA` | 登录票据，通常是**最长**的那个值 |
| `bili_jct` | CSRF token |
| `DedeUserID` | 你的数字 UID，全是数字 |

> ⚠️ 列表里还有一个 `DedeUserID__ckMd5`，**多一个后缀，不是它**，别选错。

**方法二：用项目脚本自动拼好（推荐）**

```bash
cd backend

# ① 先导出 cookies.txt（任选其一）
python export_cookies_direct.py     # 直读浏览器数据库，不用关浏览器
python export_cookies.py            # 常规方式

# ② 若已用浏览器扩展导出过 cookies.txt，直接提取三要素
python make_bili_cookie.py

# ③ 手上已有 "k=v; k2=v2" 格式时，直接转换
python make_bili_cookie.py --raw "SESSDATA=x; bili_jct=y; DedeUserID=1"
```

脚本会**直接输出一整行可粘贴的值**：

```
SESSDATA=abc123...; bili_jct=0123456...; DedeUserID=12345678
```

复制到控制台即可。程序会自动把它转成标准 Netscape 格式。

> 💡 `SESSDATA` 通常 **30 天过期**。线上解析若突然报 `No video formats found`，
> 首先怀疑它过期了 —— 重新导出并更新环境变量，然后重启服务。

<details>
<summary>如果坚持用完整 cookies.txt 内容</summary>

也可以用 `\n` 显式换行，或直接在控制台多行输入。但**分号单行格式最稳妥**。

</details>

### 5.5 部署与获取域名

1. 点击 **发布** → 等待构建完成（首次约 3-5 分钟）
2. 版本列表 → **访问公网域名** → 记下后端域名，形如：
   ```
   https://saveany-backend-xxxxx-80-xxxxxxxx.sh.run.tcloudbase.com
   ```
3. 验证：
   ```bash
   curl https://你的后端域名/api/health
   ```

## 六、第二步：部署前端服务

### 6.1 新建前端服务

环境内 → **新建服务**：

1. 服务名称：`saveany-frontend`
2. 代码源：同一仓库、同一分支 `main`
3. **代码目录**：`frontend` ← 关键
4. 端口：`80`
5. 确认创建

### 6.2 配置前端环境变量

| 变量名 | 必填 | 值 |
|--------|:----:|-----|
| `BACKEND_URL` | ✅ | 后端服务的**内网地址**或**公网域名**（见下） |

**优先用内网地址**（同环境内调用，不走公网、不计流量费）：
在**后端服务**详情页找到「内网访问地址」，形如 `http://saveany-backend:80`。

若内网地址不可用，则填后端公网域名：
```
https://saveany-backend-xxxxx-80-xxxxxxxx.sh.run.tcloudbase.com
```

> `BACKEND_URL` 会在 Nginx 容器启动时替换 `nginx/default.conf.template` 里的
> `${BACKEND_URL}`，**改完重启服务即可生效，无需重新构建镜像**。

### 6.3 部署并访问

1. **发布** → 等待构建（前端构建约 3-6 分钟）
2. 访问前端公网域名，应能看到页面

## 七、第三步：上线自检

```bash
# ① 后端健康检查
curl https://你的后端域名/api/health

# ② B 站解析（验证 BILI_COOKIE 是否生效）
curl -X POST https://你的后端域名/api/parse \
  -H "Content-Type: application/json" \
  -d '{"url":"https://www.bilibili.com/video/BV1mAAmzqEfP"}'

# ③ 前端 API 代理是否打通（应返回同样的 JSON）
curl https://你的前端域名/api/health

# ④ AI 总结（SSE 流式，应逐条推送事件）
curl -N -X POST https://你的前端域名/api/summarize \
  -H "Content-Type: application/json" \
  -d '{"url":"https://www.bilibili.com/video/BV1mAAmzqEfP"}'
```

**预期结果**：

| 检查 | 预期 |
|------|------|
| ① | `{"status":"ok",...}` |
| ② | 返回视频标题与格式列表 |
| ③ | 与 ① 相同 → 说明 Nginx 反代正常 |
| ④ | 依次收到 `subtitle` / `summary` / `mindmap` / `done` 事件 |

## 十、常见问题

### Q1：部署后数据库连接失败 / 表不存在
- 确认已开通**内置 MySQL**，且容器能读到 `MYSQL_ADDRESS`
- 首次启动会自动建库建表；若失败，看日志：服务 → 日志
- MySQL 有**自动暂停**特性（10 分钟无访问暂停），首次请求可能慢 1-2 秒，代码已做重试

### Q2：B 站解析报 `No video formats found`
1. `BILI_COOKIE` 没配或格式不对 → 用单行分号格式重新配置
2. Cookie 已过期（`SESSDATA` 约 30 天）→ 重新导出并更新环境变量
3. 云托管出口 IP 被 B 站限流（机房 IP 常见）→ 换地区或加代理

### Q3：AI 总结报 `402 Insufficient Balance`
DeepSeek 余额不足，去 https://platform.deepseek.com/top_up 充值。

### Q4：AI 总结不是流式的，等很久才一次性返回
检查前端 `BACKEND_URL` 是否走内网/公网直连而被中间层缓冲。
本项目 Nginx 已配 `proxy_buffering off`；若你额外加了 CDN，需在 CDN 侧关闭缓冲。

### Q5：前端刷新子路由 404
Nginx 的 `try_files $uri $uri/ /index.html` 已处理。若自定义了配置，注意保留这行。

### Q6：请求超时 / 长视频总结失败
- 后端的 `container.config.json` 已把 CPU 设为 0.5、内存 1G，长任务可适当调大
- 注意：**内存必须 = 2 × CPU**（平台约束）

### Q7：构建失败，提示找不到 Dockerfile
- 检查「代码目录」是否设为 `backend` / `frontend`
- `container.config.json` 的 `dockerfilePath` 是相对「代码目录」的

### Q8：想重新部署但数据不能丢
数据在 MySQL 里，**重启/重新部署容器不影响**。只有删除 MySQL 实例才会丢。
