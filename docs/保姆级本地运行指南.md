# 🚀 保姆级本地运行指南

本文档手把手教你在本地跑起来 AI 万能视频下载总结器的完整前后端，**零基础也能跟着做**。



## 前置要求

| 工具 | 版本要求 | 检查命令 | 安装方式 |
|------|----------|----------|----------|
| Python | ≥ 3.10 | `python3 --version` | [官网下载](https://www.python.org/downloads/) |
| Node.js | ≥ 18 | `node -v` | [官网下载](https://nodejs.org/en)（推荐 LTS 版本） |
| npm | ≥ 9 | `npm -v` | 随 Node.js 一起安装 |
| ffmpeg | 任意 | `ffmpeg -version` | [官网下载](https://ffmpeg.org/download.html) 或 `brew install ffmpeg`（macOS） |
| Git | 任意 | `git --version` | [官网下载](https://git-scm.com/) |

💡 关于 ffmpeg：ffmpeg 用于合并视频和音频流（如 YouTube 高清视频的画面和声音是分开的）。如果不安装，项目仍可运行，但下载高清视频时会降级为低画质单一格式。**强烈建议安装。**

## 第三步：配置环境变量

```bash
cd backend
cp .env.example .env
```

用任意文本编辑器打开 `backend/.env` 文件，填入你的配置：

```env
# ✅ 必填 - DeepSeek API Key，用于 AI 视频总结
DEEPSEEK_API_KEY=sk-你的真实key

# ✅ 必填 - JWT 密钥，用于用户登录认证
# 本地开发可以随便写一个字符串，生产环境请使用强随机值
JWT_SECRET=my-local-dev-secret-123

# 🔧 选填 - Stripe 支付配置（不配置不影响核心功能）
STRIPE_SECRET_KEY=sk_test_你的stripe密钥
STRIPE_WEBHOOK_SECRET=whsec_你的webhook密钥
STRIPE_PRICE_ID_MONTHLY=price_你的价格id

# 🔧 选填 - 前端 URL，Stripe 支付完成后跳转地址
FRONTEND_URL=http://localhost:5173
```

| 字段 | 必填 | 用途 |
|------|------|------|
| `DEEPSEEK_API_KEY` | ✅ 必填 | 调用 DeepSeek 大模型生成视频总结、思维导图、AI 问答 |
| `JWT_SECRET` | ✅ 必填 | 用户登录 Token 的签名密钥，本地开发可随意设置 |
| `STRIPE_SECRET_KEY` | 🔧 选填 | Stripe 支付 API 密钥，不填则支付功能不可用 |
| `STRIPE_WEBHOOK_SECRET` | 🔧 选填 | Stripe Webhook 签名验证密钥 |
| `STRIPE_PRICE_ID_MONTHLY` | 🔧 选填 | Stripe 月度会员的价格 ID |
| `FRONTEND_URL` | 🔧 选填 | 支付完成后跳转地址，默认 `http://localhost:5173` |

⚠️ **注意**：`.env` 文件包含敏感信息，已被 `.gitignore` 排除，不会提交到代码仓库。

## 常见问题

### Q1：`ffmpeg` 未安装，下载视频报错或画质很低？

**原因**：高清视频的画面和声音是分开的，需要 ffmpeg 合并。

**解决**：
```bash
# macOS
brew install ffmpeg

# Ubuntu / Debian
sudo apt install ffmpeg

# Windows：从 https://ffmpeg.org/download.html 下载，解压后将 bin 目录加入 PATH
```

### Q2：`yt-dlp` 版本过低，解析视频失败？

**现象**：部分视频解析失败，报错 `Unable to extract` 或 `Unsupported URL`。

**解决**：
```bash
pip install --upgrade yt-dlp
```

### Q2.1：B 站解析报 `HTTP Error 412: Precondition Failed` 或 `No video formats found`？

**现象**：

```
ERROR: [Bilibili] 1DDNzQEoQg: Unable to download webpage:
HTTP Error 412: Precondition Failed
```

或

```
ERROR: [BiliBili] BV1GJ411x7h7: No video formats found!
```

**原因**：B 站对下载工具做了三层风控，逐层触发不同报错：

| 层级 | 校验内容 | 未通过时的报错 |
|------|----------|----------------|
| 第一层 | Referer / 浏览器 UA | 412 Precondition Failed |
| 第二层 | TLS/JA3 指纹 | 412 Precondition Failed |
| 第三层 | 登录态（Cookie） | No video formats found |

**解决**（项目已内置规避逻辑，按以下步骤补齐依赖与 Cookie 即可）：

**1. 升级 yt-dlp 并安装指纹伪装依赖**

```bash
cd backend
pip install -U "yt-dlp[default,curl-cffi]"
pip install browser_cookie3
```

> 只有带 `curl-cffi` 的 yt-dlp 才能做 TLS 指纹伪装，普通请求头无法绕过第一、二层风控。

**2. 导出 B 站 Cookie（破解第三层）**

先在浏览器登录 B 站，然后按下面的顺序尝试。**建议先用自检脚本定位问题**：

```bash
cd backend
python doctor_cookies.py          # ① 一键自检：环境/权限/进程/数据库可读性
```

自检会明确告诉你卡在哪一步。常见结果与对策：

| 自检结果 | 原因 | 对策 |
|----------|------|------|
| `[3] 浏览器运行中` | Chrome/Edge 独占锁定了 Cookies 数据库 | 完全退出浏览器（含后台进程）后重试 |
| `[1] 依赖未安装` | 缺 `browser_cookie3` | `pip install browser_cookie3 pycryptodome` |
| `[4] 可读但无登录字段` | 未登录 B 站 | 先在浏览器登录 https://www.bilibili.com |
| `[4] 解密失败` | Chrome 127+ App-Bound 加密 | 用下方「方案 B」直读解密，或「方案 C」扩展导出 |

**方案 A：browser_cookie3 自动导出（最简单）**

```bash
python export_cookies.py                    # 自动尝试 Chrome / Edge
python export_cookies.py --browser edge     # 指定浏览器
```

**方案 B：直读数据库 + DPAPI 解密（不关浏览器）**

当方案 A 报 `[跳过] chrome: 返回 0 条` 时使用。它会用 Windows 共享读方式
复制数据库（**无需关闭浏览器**），再用 DPAPI 自行解密：

```bash
pip install pycryptodome
python export_cookies_direct.py             # 自动 Chrome -> Edge
python export_cookies_direct.py --browser edge
```

> 若方案 B 仍提示「全部解密失败」，说明你的 Chrome 是 127+ 且启用了
> App-Bound Encryption（v20），标准解密无法处理，请用方案 C。

**方案 C：浏览器扩展手动导出（成功率最高，兜底）**

1. 浏览器安装扩展 **「Get cookies.txt LOCALLY」**（Chrome / Edge 商店直接搜索）
2. 打开并登录 https://www.bilibili.com
3. 点击扩展图标 → **Export** → 保存文件
4. 把文件重命名为 `cookies.txt` 放到 `backend/` 目录下

成功后 `backend/cookies.txt` 会自动被程序加载。

**3. 重启后端**

```bash
python main.py
```

**验证**：

```bash
python -c "
import sys; sys.path.insert(0,'.')
from downloader import VideoDownloader
print(VideoDownloader().parse_video('https://www.bilibili.com/video/BV1mAAmzqEfP')['title'])
"
```

> 说明：`build_ydl_opts()` 会自动注入 Referer / UA / 指纹伪装 / Cookie，
> 无需在每个调用点重复配置。`cookies.txt` 含有账号凭证，请勿提交到 Git。
>
> 三个脚本的分工：
> - `doctor_cookies.py` —— 自检诊断，先跑它
> - `export_cookies.py` —— 常规导出（依赖 browser_cookie3）
> - `export_cookies_direct.py` —— 直读数据库导出（不关浏览器，兜底更强）

### Q2.2：点击下载报 `Download failed with status code 400` / `Requested format is not available`？

**现象**：解析成功，但点「下载」时前端提示下载失败，后端返回 400：

```
{"detail":{"error":"下载失败: ERROR: [BiliBili] BVxxx:
Requested format is not available. Use --list-formats ..."}}
```

**原因**：本项目解析出的最高画质是「视频流 + 音频流分离」，需要 **ffmpeg 合并**。
未安装 ffmpeg 时，`download_video()` 会降级 `format_id`，但如果降级逻辑不严谨
（旧实现直接改成 `best`），而 B 站等平台**没有 `best` 这种单文件格式**，
就会报 `Requested format is not available`。

**解决**：安装 ffmpeg（推荐，直接支持合并高清）：

```bash
pip install static-ffmpeg
```

> `static-ffmpeg` 会在首次使用时自动下载 ffmpeg 二进制，无需手动配置 PATH。
> 也可以自行安装系统版 ffmpeg 并加入 PATH，项目会自动优先使用。

安装后重启后端，`has_ffmpeg` 变为 `True`，即可下载并合并高清视频。

**验证**：

```bash
python -c "
import sys; sys.path.insert(0,'.')
from downloader import VideoDownloader
print('has_ffmpeg:', VideoDownloader().has_ffmpeg)
"
```

### Q2.3：AI 总结报 `请先登录后使用 AI 总结功能`？

**说明**：这是**设计的权限校验**，不是 Bug。AI 总结需要登录后使用：
- 未登录 → 提示登录
- 已登录免费用户 → 每日 3 次
- VIP 用户 → 不限次数

**解决**：先在页面注册并登录账号，再使用 AI 总结。

### Q2.4：AI 总结报 `总结失败: Error code: 402 - Insufficient Balance`？

**现象**：已登录，字幕能正常提取（`event: subtitle`），但随后返回：

```
event: error
data: {"message": "总结失败: Error code: 402 - Insufficient Balance"}
```

**原因**：**DeepSeek 账户余额不足**（余额为 0），不是代码问题。

**排查**：直接查询余额确认：

```bash
curl https://api.deepseek.com/user/balance \
  -H "Authorization: Bearer <你的 DEEPSEEK_API_KEY>"
```

若返回 `"total_balance":"0.00"`，即确认余额耗尽。

**解决**：前往 [DeepSeek 开放平台](https://platform.deepseek.com/top_up) 充值后即可恢复。
充值无需改代码，`.env` 中的 `DEEPSEEK_API_KEY` 保持有效。

### Q2.5：创建支付失败 `Invalid API Key provided: sk_test_********`？

**现象**：点击「开通 VIP」时弹窗：

```
创建支付失败: Invalid API Key provided: sk_test_********...key
```

**原因**：`backend/.env` 中的 Stripe 配置**还是 `.env.example` 里的占位符**，
没有替换成真实 Key。占位符 `sk_test_your_stripe_secret_key` 不是合法 Key，
调 Stripe 接口必然被拒。

**方案 A（推荐：本地测试 / 演示，不接支付）**

本项目提供支付开关，关闭后 AI 总结等会员功能**直接开放，无需登录也无需支付**：

```ini
# backend/.env
PAYMENT_DISABLED=true
```

改完**重启后端**即可。此后：
- AI 总结 / AI 问答：不校验登录、不限次数
- 「开通 VIP」按钮点击后提示"支付功能已关闭"，不会报错

**方案 B（接入真实支付）**

前往 [Stripe Dashboard](https://dashboard.stripe.com/test/apikeys) 获取测试 Key，
填入 `backend/.env`：

```ini
PAYMENT_DISABLED=false
STRIPE_SECRET_KEY=sk_test_你的真实密钥
STRIPE_PRICE_ID_MONTHLY=price_你的真实价格ID
STRIPE_WEBHOOK_SECRET=whsec_你的Webhook密钥
```

> `STRIPE_PRICE_ID_MONTHLY` 需在 Stripe 后台「商品」中先创建一个价格（Price），
> 币种建议 CNY，金额 9.90 元（对应代码里的 990 分）。

### Q3：后端启动报环境变量未设置？

**原因**：`.env` 文件未创建或 Key 未填写。

**解决**：确认 `backend/.env` 文件存在，且 `DEEPSEEK_API_KEY` 已填入有效的 Key。

### Q4：端口 8000 或 5173 被占用怎么办？

**解决**：
```bash
# 查看占用端口的进程
lsof -i :8000    # macOS / Linux

# 终止占用的进程
kill -9 <PID>
```

### Q5：前端请求后端接口返回 CORS 错误？

**解决**：确保通过 `http://localhost:5173` 访问前端页面。前端会自动将 `/api` 请求通过 Vite 代理转发到后端，本项目后端也已配置了 `allow_origins=["*"]`。

### Q6：下载抖音视频失败？

**解决**：
1. 确保使用的是抖音分享链接（如 `https://v.douyin.com/xxx`）
2. 检查网络是否正常，抖音接口可能有频率限制
3. 尝试升级 yt-dlp：`pip install --upgrade yt-dlp`

### Q7：Stripe 支付功能测试不成功？

**解决**：
1. 确保 `.env` 中三个 Stripe 配置项都已填写
2. 确保 Stripe Dashboard 处于「测试模式」
3. 测试支付时使用 Stripe 提供的测试卡号：`4242 4242 4242 4242`
4. 本地测试 Webhook 需运行 Stripe CLI：
   ```bash
   stripe listen --forward-to localhost:8000/api/payment/webhook
   ```

### Q8：`pip install` 安装依赖报错？

**常见情况**：
- **bcrypt 编译失败**：安装 C 编译工具。macOS 运行 `xcode-select --install`
- **Python 版本过低**：需要 Python ≥ 3.10
- **网络超时**：使用国内镜像 `-i https://pypi.tuna.tsinghua.edu.cn/simple`

### Q9：Windows 系统运行终端命令报错？

**解决**：建议在 VSCode 中把默认终端改为 Git Bash，或使用 PowerShell。避免使用 CMD。



## 停止项目

在各终端窗口按 `Ctrl + C` 即可停止前后端服务。

数据库文件（`backend/data/app.db`）会保留，下次启动时数据不会丢失。
